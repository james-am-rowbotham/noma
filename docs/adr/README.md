# Decision records

Why Noma is the way it is. The code says what it does; these say why, and what lost.

**Before writing one, run the test in CLAUDE.md (*Where writing goes*) and stop at the first
match.** A record is the LAST option. It is the right home only when this is WHY, with alternatives
that lost or measurements behind it.

## Writing one

Copy [`0000-template.md`](0000-template.md) into the directory for its concern and take the next
free number **in that directory**. The `adr` skill in `.claude/skills/` walks through it.

| Sequence | Lives in | Covers |
|---|---|---|
| `ADR-NNNN` | `architecture/` | system, data, scientific pipeline, infrastructure, tooling |
| `DESIGN-NNNN` | `design/` | the interface: interaction, the component system, how provenance and uncertainty are shown |

**One sequence per concern, and the prefix is part of the reference.** The split is so two
sessions working on different concerns cannot collide on a number. Always write the prefix in
prose and in code comments — a bare `0007` is ambiguous.

Accepted records are **immutable except for a forward pointer** — `status`, `superseded-by`,
`amended-by`, and a one-line note under the title saying which part moved. A reversal is a new
record with `supersedes:`; a change that leaves the old reasoning intact uses `amends:`. The old
one always stays.

**Carry evidence over verbatim.** A record that summarises its own measurements has kept the word
count and thrown away what the words were for.

`scripts/adrIntegrity.test.ts` enforces the structure: unique ids, filename matching the declared
id, type matching directory, every cross-reference resolving, symmetric supersession and
amendment, `pinned-by` files that exist, alternatives present in every accepted record, and the
index below matching disk.
